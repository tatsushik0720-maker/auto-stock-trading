# 株の架空売買シミュレータ

日足データで売買ルールを検証するための**架空**売買シミュレータです。
実際の注文や証券口座への接続は一切行いません。

## 使い方

```bash
pip install -r requirements.txt
python run.py                    # config.yaml の設定で実行
python run.py --fee-rate 0.001   # 手数料だけ 0.1% にして比較（ファイルは書き換えない）
python compare.py                # 売買の少ない戦略を、期間を分けて比べる
python compare_ml.py             # 機械学習の戦略を、放置・25日平均・答えを入れ替えた版と比べる
python forward.py                # フォワードテストを1日分進める（毎日1回）
python -m pytest                 # テスト
```

銘柄・資金・期間・戦略は **`config.yaml` だけ**を書き換えて変更します。

## データについて

- 取得した日足は `data/銘柄.csv` に保存し、次回からは足りない分だけ取得します。
- ネットにつながらないときは、保存済みデータで続けます（警告が出ます）。
- Yahoo のデータには、株式分割の直後だけ価格が 1/10・1/100 のまま入っている誤りが
  見つかっています（1321.T: 2026-10-05〜06、1306.T: 2026-03-30〜31）。
  前後の日と比べて 1/10・1/100 にずれ、元に戻っている日だけを自動で直し、内容を表示します。
- 出来高0の行（祝日などに前日の値を入れた行）や欠けている日は、前日の値で埋めず
  「その銘柄はその日は取引なし」として扱います。
- 売買単位は JPX「銘柄一覧（ETF）」の Trading Unit 欄で確認できます。

## 売買のルール（シミュレータ）

- 終値で合図 → 次にその銘柄の取引がある日の始値で約定（未来の価格は使わない）
- 買いは始値×(1+値差率)、売りは始値×(1−値差率)。売買単位(lot_size)未満の端数は現金のまま
- 積立は開始月の翌月から、毎月最初の取引日に入金。初期資金と積立は銘柄数で等分
- 取得価格は総平均法（手数料込み）。税は同じ年の損益を通算し、売却のたびに精算
- 結果は `output/trades.csv`（売買1回ごと）、`output/daily.csv`（銘柄ごとの日次）、
  `output/portfolio.csv`（合計の日次）に出ます

## 評価の見方（output/）

| ファイル | 中身 |
|---|---|
| `summary.csv` | 戦略と「最初に買って放置」（同じ資金・積立・コスト）の比較表 |
| `yearly.csv` | 年ごとの損益と、どちらが勝ったか |
| `equity.png` | 資産推移（戦略・放置・投入総額）とドローダウン推移 |
| `game.html` | 対戦ゲーム風の画面（下の「対戦画面」を参照） |
| `trades.csv` / `buy_and_hold_trades.csv` | 売買1回ごとの記録 |

- 損益 = 最終資産 − 投入総額（積立は利益ではないので除く）
- 最大ドローダウンと年ごとのリターンは、入金の影響を除いた時間加重リターンで計算
  （積立で資産が増えると、下落が小さく見えてしまうため）

## 戦略の比較（compare.py）

`config.yaml` の `comparison` に書いた戦略を、同じ資金・積立・コストで通しで動かし、
成績を「選ぶ期間」（初期値 2018〜2022年）と「確かめる期間」（2023年〜最新）に分けて測ります。
選ぶ期間の年率リターンが一番良い戦略を選び、確かめる期間でも「最初に買って放置」と比べて、
選ぶ期間だけ良かった場合はそう表示します。結果は `output/compare.csv`。

| 戦略名 | 中身 | パラメータ |
|---|---|---|
| `sma_cross` | 終値が平均より上で買い、下で売り | `window` |
| `sma_band` | 平均×(1+band) を上回ったら買い、平均×(1−band) を下回ったら売り。帯の中は前の判断のまま | `window`, `band`（0.02 = 2%） |
| `sma_cooldown` | `sma_cross` と同じだが、買い⇄売りを切り替えたら `cooldown` 営業日は次の切り替えをしない | `window`, `cooldown` |

- 平均を出すのに必要な日数分、データは選ぶ期間より前から読み込みます（200日平均でも初日から判断できる）
- 期間の初めに持っている株はそのまま持ち越します（口座は途中でリセットしない）
- 売買回数は積立分の買い増しも1回と数えます。かっこ内は売りの回数
- `sma_cooldown` が止めるのは買い⇄売りの切り替えだけで、買いの状態のときの積立分の買い増しは止めません

## 機械学習の戦略（compare_ml.py）

`ml_logistic` は、ロジスティック回帰で「この先5営業日で上がるか」を予想し、
確率が `threshold` 以上のときだけ持つ戦略です（numpy だけで書いていて、追加の部品は要りません）。

| | 中身 |
|---|---|
| 特徴 | 直近5日・20日・60日の値動き、25日・75日移動平均からの離れ具合、20日の値動きの荒さ（日々の対数変化率の標準偏差） |
| 答え | `horizon`（既定5）営業日後の終値が、その日の終値より高ければ 1 |
| 学び直し | `retrain_months`（既定3）か月ごと（1・4・7・10月の最初の取引日）。その日の終値までで答えが確定している日だけで学ぶ |
| 合図 | 予想の確率が `threshold` 以上なら買い、未満なら売り。学ぶデータが `min_train`（既定500日）に満たないあいだは様子見 |
| 対照 | `shuffle_seed` を付けると、学び直しのたびに答えだけを並べ替えてから学ぶ「答えを入れ替えた版」になる |

`python compare_ml.py` は、`ml_comparison.candidates`（確率の基準違い）・25日移動平均・放置を、
`comparison` と同じ「選ぶ期間」と「確かめる期間」に分けて比べます。
選ぶ期間で一番良かった基準について、答えを入れ替えた版を `shuffle_runs`（既定20）通り動かし、
本物が **両方の期間の AUC（予想の当たり具合）と確かめる期間の年率で、入れ替え版の全部を上回ったときだけ**
「パターンがあった可能性がある」とします。それ以外は「パターンは見つからなかった」と表示します。
結果は `output/compare_ml.csv`・`compare_ml_shuffle.csv`・`compare_ml.txt`・`game_compare_ml.html`。

未来のデータが混ざらないことは `tests/test_ml.py` で確かめています。

- ある日より後の株価をでたらめに書き換えても、その日までの判断と確率が1つも変わらない
- 学習データの答えは、学び直す日までの終値だけで作られている
- パターンのない値動き（ランダムウォーク）では、予想が当てずっぽう並み（AUC 0.5 前後）になる
- パターンを仕込んだ値動きでは見つけられ、答えを入れ替えると見つからなくなる

わざと未来の終値を学習に混ぜた版では、このうち3件のテストが落ちることも確かめました。

### 結果（2026-11-08 時点。2018〜2022年で選び、2023年〜2026-11-06 で確かめた）

| 戦略 | 選 年率 | 選 最大DD | 選 売買回数 | 選 値差負担 | 確 年率 | 確 最大DD | 確 売買回数 | 確 値差負担 |
|---|---|---|---|---|---|---|---|---|
| 最初に買って放置 | +1.3% | −32.1% | 125(0) | 1,087円 | +21.2% | −23.7% | 94(0) | 464円 |
| 移動平均25日 | −3.1% | −26.6% | 359(149) | 116,212円 | +8.3% | −22.0% | 259(98) | 135,548円 |
| **機械学習 確率60%以上**（選ばれた） | −3.1% | −26.5% | 147(69) | 45,812円 | +8.6% | −14.7% | 98(45) | 77,946円 |
| 機械学習 確率50%以上 | −3.3% | −39.9% | 282(88) | 57,483円 | +20.9% | −24.0% | 182(49) | 79,854円 |
| 機械学習 確率55%以上 | −5.4% | −36.9% | 441(196) | 134,495円 | +7.4% | −22.4% | 263(112) | 151,680円 |

- 選ばれた「確率60%以上」は、放置に両方の期間で負けた（確かめる期間は −12.7pt）
- 答えを入れ替えた版20通りとの比較では、確かめる期間の AUC は本物 0.548 が全部を上回った。
  しかし選ぶ期間の AUC は本物 0.480 で、当てずっぽうを下回り、入れ替え版20通りのうち11通りに負けた
- 判定：**パターンは見つからなかった**。期間によって当たったり外れたりしていて、安定した予想になっていない

## 対戦画面（game.html）

`run.py` は最後に `output/game.html`、`compare.py` は `output/game_compare.html` を書き出します。
サーバーは要らず、ブラウザで開くだけで動きます（外部の部品を使わないので、ネットなしでも開けます）。

- 「戦略くん」と「放置くん」が同じ資金から対戦。再生（1倍＝1秒に10営業日、5倍・20倍）、一時停止、スライダー
- 資産はカウンター表示、線グラフは再生に合わせて伸びる。▲買い ▼売り（積立の買い増しは記録欄にだけ出す）
- 名場面ジャンプ: 一番大きな急落・一番強い上昇相場・最大の落ち込みの始まり・最大のリードを結果から自動で選ぶ
- 実況: 売買・逆転・リードの節目（10万円ごと）・1日で4%以上の値動きのときに短い文を出す
- 最後に結果画面（最終資産・損益・最大の落ち込み・売買回数・値差の負担額・勝者）
- `game_compare.html` は上の欄で「戦略くん」の中身を切り替えられる（選ぶ期間で良かった順）
- 「過去のリプレイ」と「フォワードテスト」の切り替えつき。フォワードテストは `sim.game.write_game(パス, リプレイ, フォワード)` の
  3つ目にデータを渡すと表示される（今はまだ無いので「準備中」）

`compare.py` は段階7から、売買と入金を選ぶ期間の初日（2018-01-04）から始めます。
それより前のデータは平均の計算にだけ使います（以前は 2017年2月から売買していた）。

## フォワードテスト（forward.py）

毎日の実際の値動きで、架空売買を1日ずつ続けます。バックテストの口座（output/）とは別に、
`forward/` に状態と記録を保存し、GitHub にも上げます。実際の注文は一切出しません。

### 設定（config.yaml の `forward`）

```yaml
forward:
  start: "2026-11-08"      # 開始日
  dir: forward             # 保存先
  benchmark: hold          # 比べる相手（「放置」）の id
  strategies:
    - {id: sma25, name: sma_cross, params: {window: 25}}
    - {id: hold, name: buy_and_hold}
```

- 銘柄・資金（50万円）・積立（月1万円）・コストは、config.yaml の上の設定をそのまま使います
- **始めたあとに上の設定（銘柄・資金・積立・コスト）を変えると、保存した口座と合わないため
  forward.py はエラーで止まります。** バックテストで設定を試すときは、別の設定ファイルを
  `python run.py --config 別の設定.yaml` で使ってください
- 戦略を足すときは `strategies` に1行足し、`start` に足した日を書きます。
  例: `- {id: band25, name: sma_band, params: {window: 25, band: 0.02}, start: "2026-12-01"}`
  （`start` を書かないと、forward.start までさかのぼって動かします）
- `id` は保存ファイルの名前です。一度決めたら変えないでください

### 毎日の実行

```bash
python forward.py
```

この1コマンドで、次のところまで進みます。

1. 株価を取得する（`data/` に保存済みの分は取り直さない）
2. 戦略ごとに、前回処理した日より後の取引日だけを処理する
   - 前の取引日に記録した架空の注文を、その日の始値で約定させる
   - その日の終値で合図を判定し、翌取引日の始値で約定させる注文を記録する
3. `forward/` に状態と記録を保存する
4. `forward/` だけをコミットして `git push` する（ほかの変更は混ぜない）
5. 最後に、その日の結果を短い文章で表示する（通知に使う）

- 土日祝や、株価がまだ更新されていない日は、何も書かずに終わります。
  更新が遅れていただけなら、次の実行でまとめて処理します（結果は毎日動かした場合と同じ）
- 同じ日に2回動かしても、二重には処理しません
- 失敗したときは `[失敗] 原因` を表示し、終了コード 1 で終わります。
  push だけ失敗した場合、記録はコミット済みで、次回の実行でまとめて push します
- 株式分割などで、処理済みの日の価格が後から変わっていたら止まります
  （保有口数と価格が合わなくなるため。状態ファイルを直してから再実行します）
- `--no-push` でコミットと push をしない、`--dry-run` で何も保存しない

平日 18:30（日本時間）に、Claude のスケジュールタスクから実行しています。

### 約定の想定ずれ（execution_check.csv）

将来、本物のお金に移るかを判断するためのデータです。証券会社への接続や実際の注文はしません。
「終値を見て判定し、翌朝の寄付で注文する」やり方で、思った値段・口数で約定できるかを1件ずつ残します。

| 列 | 意味 |
|---|---|
| 合図の日の終値 / 約定日の始値 | 判定に使った値段と、約定させた値段 |
| 寄りの窓 | 始値 ÷ 合図の日の終値 − 1（夜の間の値動き） |
| 終値からの不利なずれ | 買いなら高く、売りなら安く約定した割合（プラスが不利）。値差込み |
| 想定した値差率 | 設定の slippage_rate。実際のずれがこれより大きいことが多ければ、設定が甘い |
| 見込み口数 / 約定口数 | 終値で見込んだ口数と、始値で実際に買えた口数 |
| 間に合ったか | 注文を記録した時刻が、約定日の 9:00 より前か。遅れていたら、本番なら寄付に間に合っていない |

「注文の記録なし（終値では買えない見込みだった）」は、終値では1単位も買えない見込みだったのに、
始値が下がって買えた約定です。本番では注文を出していないので起きない約定、として見ます。

## 口座の状態の保存と再開（フォワードテストの準備）

実行の最後に、架空口座の状態を `output/state.json` に保存します
（銘柄ごとの現金・保有口数・平均取得価格・未約定の注文、その年の通算損益と税など）。
`run_simulation(..., state=SimState.load(パス))` で、保存した日の翌日から続きを処理できます。

- 途中で保存して再開しても、一度に動かした結果と完全に一致します（テスト済み）
- 同じデータで2回動かしても、処理済みの日は飛ばすので二重に売買しません
- 保存時と設定（銘柄・売買単位・コスト・戦略）が違うと、混ぜずにエラーで止めます
- 保存は一時ファイル経由で行い、前回分を `state.json.bak` に残します
- 戦略は「その日までの株価」だけで判断し、戦略の中に記憶を持たない決まりにしています

## 戦略の追加

`src/sim/strategies/` に1ファイル置き、`Strategy` を継承したクラスに
`name` と `decide()` を書くと、`config.yaml` の `strategy.name` で使えます。
`decide()` が受け取る `DayContext` には、その日までの株価・保有株数・追加情報
（`extras`。将来のニュース判定用）が入っています。

## フォルダ構成

```
config.yaml        設定（ここだけ触る）
run.py             実行入口
compare.py         売買の少ない戦略の比較
compare_ml.py      機械学習の戦略の比較
src/sim/           本体（config.py など）
tests/             テスト（ネット接続不要）
data/  output/     取得データと結果（git管理外）
```
